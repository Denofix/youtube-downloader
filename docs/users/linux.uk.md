# Download & Convert - Linux

[English](linux.en.md)

Встановлення, налаштування та використання. Команди розраховані на **Ubuntu 24.04 LTS**, Desktop, Server або VMware. Для інших дистрибутивів скористайтеся [офіційною інструкцією Docker Engine](https://docs.docker.com/engine/install/), встановіть Compose plugin і продовжуйте з розділу 2. Виконуйте команди **по одній, згори вниз**; не копіюйте позначку запрошення `$`.

## 1. Підготуйте Ubuntu

Якщо Docker і `docker compose` уже працюють, залиште наявне встановлення. На чистій Ubuntu встановіть пакети з репозиторію Ubuntu:

```bash
sudo apt update
sudo apt install -y git curl software-properties-common
sudo add-apt-repository -y universe
sudo apt update
sudo apt install -y docker.io docker-compose-v2 docker-buildx
sudo systemctl enable --now docker
git --version
sudo docker compose version
sudo docker run --rm hello-world
```

Очікується `Hello from Docker!`. Пакети: [docker.io](https://packages.ubuntu.com/noble/docker.io), [docker-compose-v2](https://packages.ubuntu.com/noble/docker-compose-v2), [docker-buildx](https://packages.ubuntu.com/noble/docker-buildx). Інший спосіб - [встановлення з репозиторію Docker](https://docs.docker.com/engine/install/ubuntu/). Не змішуйте способи на вже налаштованому сервері.

Команди Docker тут виконуються із `sudo`; символи пароля не відображаються. Git запускайте від свого звичайного користувача. Python, Node.js і FFmpeg уже входять до образу платформи.

## 2. Виберіть папку та завантажте проєкт

Виберіть **будь-яку зручну батьківську папку**. Відкрийте в ній термінал через пункт файлового менеджера **Відкрити в терміналі** або перейдіть до неї командою `cd`. Потім виконайте:

```bash
git clone --branch main https://github.com/Denofix/youtube-downloader.git
cd youtube-downloader
ls compose.yaml Dockerfile
```

Git створить вкладену папку `youtube-downloader`. Усі наступні команди виконуйте з цієї папки проєкту. Шляхи з пробілами беріть у лапки. Якщо проєкт уже завантажено, відкрийте його наявну папку та скористайтеся розділом оновлення. На Ubuntu Desktop команда `xdg-open .` відкриває папку; на сервері графічний інтерфейс не потрібен.

## 3. Налаштуйте та запустіть

```bash
[ -f .env ] || cp .env.example .env
sudo docker compose config --quiet
sudo docker compose up -d --build --wait
sudo docker compose ps
curl -fsS http://127.0.0.1:8080/api/health
```

Дочекайтеся завершення першої збірки. Мають працювати обидва сервіси: `api` та `worker`. Відповідь перевірки стану має містити `"status":"ok"` і `"worker_online":true`. Якщо обробник ще запускається, повторіть запит за кілька секунд. У браузері **на цій Ubuntu** відкрийте [http://localhost:8080](http://localhost:8080).

Щоб змінити конфігурацію, використайте `nano .env`, збережіть файл і знову виконайте `sudo docker compose up -d --build --wait`.

| Параметр | Типове значення | Призначення |
| --- | --- | --- |
| `PORT` | `8080` | Локальний порт сайту; для `8081` відкривайте `http://localhost:8081` |
| `MAX_FILE_BYTES` | `536870912` | До 512 МіБ на файл |
| `MAX_STORAGE_BYTES` | `5368709120` | До 5 ГіБ медіафайлів у сховищі |
| `RESULT_TTL_SECONDS` | `86400` | Зберігання файлів протягом 24 годин |
| `JOB_TIMEOUT_SECONDS` | `1800` | До 30 хвилин на одне завдання |

Налаштування показують значення сервера; змінювати їх потрібно у `.env`. Для звичайного використання ключі API не потрібні. Доступ залежить від публікації та платформи. Типово сервіс слухає лише `127.0.0.1`.

## 4. Доступ до VM або сервера з іншого комп'ютера

Якщо SSH ще не налаштовано, підготуйте його **в Ubuntu**:

```bash
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
whoami
hostname -I
```

У PowerShell або терміналі **основного комп'ютера** замініть `USER` та `UBUNTU_IP` на ім'я користувача Ubuntu й доступну в мережі IP-адресу Ubuntu:

```text
ssh -N -L 18080:127.0.0.1:8080 USER@UBUNTU_IP
```

Залиште цей термінал відкритим і перейдіть на [http://localhost:18080](http://localhost:18080). Потрібен мережевий доступ до SSH-сервісу Ubuntu. Якщо ви змінили `PORT`, замініть останній `8080` у команді тунелю. Основний комп'ютер і VM мають різні адреси `localhost`. За стандартного прив'язування до loopback прямий доступ до IP-адреси VM через порт 8080 не працює.

## 5. Користуйтеся платформою

Праворуч угорі виберіть **English / Українська**. Браузер запам'ятає вибір.

| Розділ | Що робити |
| --- | --- |
| **Завантаження** | Вставте посилання на одну публічну публікацію YouTube, TikTok, Instagram або Pinterest чи трек SoundCloud. Натисніть **Аналізувати посилання**, виберіть формат, якість або елементи та додайте завантаження до черги. Кілька вибраних елементів також доступні в ZIP. |
| **Завдання** | Дочекайтеся стану **Завершено**, завантажте результат і відкрийте його. Тут можна скасувати або повторити завдання, перевірити строк зберігання чи конвертувати збережений файл. |
| **Конвертація** | Завантажте один локальний файл, дочекайтеся перевірки, виберіть перетворення та налаштуйте бітрейт чи параметри GIF. Додайте завдання до черги. Приклади: відео зі звуком у MP3, PNG у WebP, відео в короткий GIF. |
| **Налаштування** | Перевірте стан обробника, версії інструментів, ліміти та використання сховища. |

Почніть із короткого відео та невеликого зображення. Перевірте зображення і звук у відео, рух у GIF і вміст ZIP. Для MP3 потрібна аудіодоріжка. Збільшення бітрейту не відновлює втрачену якість. Пакетне завантаження, сканування каналів/профілів і списки відтворення поки не підтримуються.

## 6. Оновлення, зупинка та повторний запуск

Відкрийте термінал **у наявній папці проєкту** та виконайте в такому порядку:

```bash
git fetch origin
git switch main
git pull --ff-only
sudo docker compose up -d --build --wait
```

Натисніть **Ctrl+F5**. Після змін у роботі з джерелами проаналізуйте посилання знову. Перед перемиканням збережіть локальні зміни Git; для звичайного оновлення `reset --hard` не потрібен.

За потреби виконуйте ці команди окремо:

```bash
sudo docker compose stop
sudo docker compose up -d --wait
sudo docker compose logs --tail 80 api worker
```

Вони відповідно зупиняють сервіси, запускають їх знову та показують останні логи. Історія й файли зберігаються в постійному Docker-томі. `docker compose down` залишає його, а **`docker compose down -v` видаляє дані**.

## 7. Усунення проблем

| Симптом | Дія |
| --- | --- |
| Docker повідомляє `permission denied` | Виконуйте команди Docker із `sudo`, як показано вище |
| `Cannot connect to the Docker daemon` | Перевірте `sudo systemctl status docker`; запустіть через `sudo systemctl start docker` |
| `no configuration file provided` | Відкрийте корінь репозиторію з `compose.yaml`; спочатку оновіть Git |
| Порт зайнятий | Виберіть вільний `PORT` у `.env`, перестворіть сервіси та використовуйте нову адресу |
| Завдання залишаються в черзі | Перевірте `worker_online`, сервіс `worker` і логи |
| Сайт не відкривається з основного комп'ютера | Перевірте SSH-тунель і відкрийте `localhost:18080` на основному комп'ютері |
| Інтерфейс виглядає застарілим | Дочекайтеся успішної збірки та натисніть Ctrl+F5 |

Для розбору проблеми збережіть текст помилки, вивід `sudo docker compose ps` та останні логи. [Репозиторій](https://github.com/Denofix/youtube-downloader) · [Матриця конвертера](../media-service/converter-matrix.md) · [Експлуатація та резервні копії](../media-service/operations.md).
